title: "Cloning dbt relations"
sidebarTitle: "Clone"

---

`sqb dbt clone` populates a target with selected, already-built relations from your production baseline without materializing them through `dbt run` or `dbt build`. It compiles the current and configured production-ref projects to resolve relation metadata, then clones or copies each selected relation into the target schema.

```bash
sqb dbt clone --select path:models/marts
```

```
sqb clone  origin=main destination=dev

  agg_daily_revenue    OK     copied
  dim_customers        OK     copied
  fct_orders           OK     copied
  ...

CLONED=0  COPIED=10  RECREATED_VIEWS=0  PASS=10  WARN=0  FAIL=0  TOTAL=10
```

The origin is the `production_ref.git_ref` from your configuration; the destination is the active target. Where the warehouse supports zero-copy cloning, relations are cloned (`CLONED`); otherwise they are copied (`COPIED`). Views are recreated to point at the cloned relations (`RECREATED_VIEWS`).

`sqb dbt clone` is an explicit standalone operation. An explicit `--select` is required; SQLBuild refuses an unscoped whole-project clone.

## Options

| Flag | Effect |
|------|--------|
| `--select` / `-s` | Required. Select matching models with dbt selection syntax. |
| `--exclude` | Exclude matching models. |
| `--hard-copy` | Force a full copy instead of a zero-copy clone, even where the warehouse supports cloning. |

```bash
sqb dbt clone --select path:models/marts
sqb dbt clone --select tag:reference --hard-copy
```
